Kaia

A personal AI assistant running in production, not on a laptop. Text chat, browser voice, and real inbound and outbound phone calls, with Claude tool-calling across Google Calendar, Gmail and a Sheets CRM.

Talk to Kaia Source

Sixteen tools across Google Calendar, Gmail and a Sheets CRM, Postgres with row-level security on every table, and per-provider cost tracking. About 10,000 lines across FastAPI and Next.js 15, on a Hetzner VPS behind Caddy.

Spreadsheets do not touch the retrieval path

Ask for a total over €5,000 and a vector search returns rows that look like the answer, so the model invents a confident number. Retrieval is the wrong tool for arithmetic.

Instead the model inspects the real schema, writes pandas, and the code runs in an isolated subprocess as an unprivileged user under CPU, memory, file-descriptor and process limits. The number is computed, not recalled.

The process limit cannot be zero. Root ignores it but an unprivileged child does not, so OpenBLAS fails to start its threads and import pandas dies before any model-written code runs. It is capped at 64 instead, which still bounds a fork bomb.

Voice: 0.20s to first audio

It used to sound like stitched-together clips, because every sentence was its own HTTPS request with a fresh TLS handshake and its own intonation curve. Now one WebSocket stays open and LLM tokens stream straight into it. First audio at 0.20s, one continuous voice.

Turn-taking was the harder bug. It keyed off is_final, which only means a chunk will not be revised, so it fires mid-sentence and Kaia kept answering fragments of my own sentences. speech_final fixed it. Two hours of confusion, one word of difference.

Safe enough to hand to a stranger

Per-person revocable access codes with message and call quotas, a restricted guest tool allowlist, Fernet-encrypted OAuth tokens, outbound calls hard-locked to a single number, and a daily spend ceiling. All of it enforced in code rather than in a prompt, because a prompt is the first thing a visitor attacks.
